# 优先时段硬软约束语义修复

## 1. 修复结论

`preferred_periods` 现在严格遵循用户选择的硬/软级别和权重：硬约束只生成所选课节的候选时间，软约束保留其他时间但按该条规则配置的权重计入时间罚分。此前固定使用 100 分且忽略硬约束级别的行为已移除。

## 2. 编译规则

- 参数 `periods` 使用作息表的零基 `period_index`；
- 硬规则：非所选 period 在构建 `problem.xml` 时直接不生成；
- 软规则：每落入一个非所选 period，增加该规则的 `weight`；
- 多条硬规则同时启用时取交集，即时间必须满足每一条硬规则；
- 多条软规则同时启用时罚分相加；
- 非负整数以外的 period 值不会进入允许集合。

硬规则若导致某课次没有任何候选，会在运行前得到 `LESSON_HAS_NO_TIME_OPTION`，不会伪造候选。软规则的罚分仍是非负值，因此零罚分候选可以使用理论下界快速结束。

## 3. 自动验收

- 两课次只能占第一、第二节，软规则“优先第二节”、权重 7：总分精确为 7，而不是固定 100；
- 增加周二第二节并设置“只能第二节”硬规则：两个课次分布到周一/周二，开始课节均为第二节；
- 硬规则候选总分为 0；
- 评分明细中的 `time_penalty` 与总分关系保持一致；
- 全量排课、无解诊断和 6000 课次性能回归继续通过。
