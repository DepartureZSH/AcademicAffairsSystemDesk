# 教务业务零出站网络自动验收

## 1. 模块结论

“学校、教师、班级、课程、约束、课表和算法输入输出不得上传”现已增加可重复的自动化门禁，而不只依赖代码审查或抓包观察。测试在 Python 进程中替换 TCP、UDP 网络发送入口，任何连接尝试都会立即失败并记录目标。

## 2. 覆盖流程

网络被完全禁止时，自动测试连续执行：

1. 新建项目并写入学期、作息、教师、课程和班级；
2. 生成教学任务和课次；
3. 在本机运行 CP-SAT 排课并生成候选；
4. 导出 Excel 课表；
5. 创建、校验并隔离恢复 `.sttbackup`；
6. 创建、校验并重新导入 `.sttproj`。

所有步骤成功后还必须断言网络尝试列表为空。因此后续代码若在业务 repository、算法、导出、备份或迁移路径中引入任意 TCP/UDP 访问，CI 会直接失败。

## 3. 与远程身份的边界

本门禁针对教务业务和算法层。Supabase Auth、许可证续签、购买会话和更新检查属于 Rust 可信层的显式远程能力，不经过 Python sidecar，也不出现在项目快照和算法输入中。开发配置只允许本机 HTTP；预发布和生产服务配置必须使用 HTTPS。

旧网页版 PostgreSQL 迁移是用户主动触发的只读导入工具，不属于常规项目流程。它只接收独立环境变量引用，导入完成后目标数据进入本地 SQLite；正式验收仍需用系统级抓包复核进程和目标域名白名单。

## 4. 验收边界

进程级 socket 拦截能够防止 Python 代码直接联网，但不能替代 Windows 对安装包、Rust 身份请求和操作系统组件的系统级观测。干净 Windows 验收阶段仍需记录应用未登录、已授权离线、排课、导出和备份场景的连接目标，并确认没有教务请求体出站。
