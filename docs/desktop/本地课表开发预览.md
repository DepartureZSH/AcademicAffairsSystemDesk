# 本地课表开发预览

## 启动与打开

在桌面版独立仓库中运行（不要在网页版 STT 目录运行）：

```powershell
Set-Location E:\Desktop\Work\Oasis\STT_desktop
npm.cmd run dev:browser --prefix apps/desktop
```

打开 <http://127.0.0.1:1420/dev.html>，也可在 Codex 的浏览器面板输入该地址。
终端保持运行；按 Ctrl+C 停止。修改 Vue、TypeScript、CSS 会热更新。
修改 Python 本地服务后需重启该命令。

第一次需要先安装前端依赖，并建立 Python 环境：

```powershell
npm.cmd ci --prefix apps/desktop
uv sync --extra dev
```

默认使用仓库 `.venv` 中的 Python；也可通过 `STT_DEV_PYTHON` 指定 Python 可执行文件路径。
端口 1420 被占用时先停止另一个开发服务，不要同时启动 `dev` 与 `dev:browser`。

## 数据与边界

- 浏览器预览打开独立的“本地界面测试项目”，数据实际保存在 `.local/browser-dev/` 下的 SQLite 项目中，刷新和重启后保留。
- 模板编辑后点击“保存”；学期周数自动保存。修改旧模板前创建本地备份。
- 不读取 `.env`，不连接账号、支付、许可证或远程学校数据服务，不改动用户正式工作目录。
- 页面与桌面版使用同一份 `CalendarView` 和本地存储接口，不是静态演示截图。
- 开发入口提供课表设置、教室设置、学校数据、约束配置和排课运行，使用同一隔离项目；桌面文件对话框、账号登录、安装更新不在浏览器验证范围内。
- 本地代理只监听回环地址；会话令牌仅在 Vite/Python 进程之间传递，不发送给浏览器。
- `dev.html`、模拟 IPC 和预览代理不进入正式安装包；正式版本的身份门禁不变。

## 网页版同步来源

源目录为相邻仓库 `STT/apps/web-admin/src`。复用当前 `TimetableSettingsView.vue` 的课表设置主体、课程单元格属性面板、模板预览、规划模式与搜索选择器，及 `useAppController.ts` 中实际使用的编辑函数。未复制旧版星期折叠编辑器。

保留新建模板三步流程、独立/复用节次、固定/弹性时段、可视网格、自定义表头/行/列、合并与拆分、导出样式和 Excel 预览。排除 AI、机构发布、公共模板上传和付费定制入口，模板库改为本地模板及内置模板。

`scripts/extract-web-timetable.cjs` 使用 TypeScript 符号依赖提取编辑逻辑，并限定样式作用域；`scripts/web-timetable-local-adapter.txt` 是本地持久化替换层。更新源版本后运行：

```powershell
node scripts/extract-web-timetable.cjs
npm.cmd run build --prefix apps/desktop
.venv\Scripts\python.exe -m pytest tests/test_timetable_settings.py tests/test_sidecar_api.py
```

重新提取会覆盖 `src/web-timetable/`，先保存改动并评审差异。网页版和桌面版的单元时间含义不同：页面按从 1 开始的节次显示，SQLite/算法继续采用从 0 开始的课节序号；不能把五分钟刻度直接写成算法课节。布局元数据保存在原有 `display_config` 内，无需破坏性 schema 迁移。
