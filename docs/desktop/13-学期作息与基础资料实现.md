# 学期作息与基础资料实现记录

## 1. 本模块范围

当前项目打开后，桌面导航开放以下两个本地模块：

- 学期与作息：学年、学期、作息表、课节；
- 基础资料：年级、教师、教室类型、教室、班级、科目。

每类数据均支持新增、编辑、列表和删除。删除操作在界面要求二次确认；SQLite 外键会阻止破坏仍被课程计划引用的数据。业务字段、唯一约束、检查约束和引用关系由本地 schema 强制执行，而不是只依赖前端表单。

## 2. 本地写入协议

页面通过 Tauri 代理调用：

- `GET /v1/data/{entity_type}`；
- `PUT /v1/data/{entity_type}`；
- `DELETE /v1/data/{entity_type}/{entity_id}?expected_revision=...`。

每次 PUT/DELETE 都携带当前项目 `expected_revision`。Sidecar 在 `BEGIN IMMEDIATE` 后重新读取实际 revision；不匹配则返回 `REVISION_CONFLICT`，防止旧页面静默覆盖新数据。成功写入会在同一事务内递增 revision，再原子更新 `manifest.json`。

本模块修正了 Vue 适配层的字段名，统一按协议发送 `expected_revision`。本地 API 错误在界面只展示安全消息和 correlation ID，不再直接展示 JSON envelope。

## 3. 进程崩溃后的项目锁

早期锁使用“独占创建 `.stt.lock` 文件”。如果 Sidecar 被 Tauri 强制终止，文件会残留，下一次启动错误判断项目仍被占用。

现改为操作系统级文件锁：

- Windows 使用 `msvcrt.locking(..., LK_NBLCK, 1)`；
- Unix 使用 `fcntl.flock(..., LOCK_EX | LOCK_NB)`；
- 文件描述符在项目打开期间持续持有；
- 进程正常退出、崩溃或被终止时，内核都会释放锁；
- `.stt.lock` 文件可以残留作为最后一次打开信息，但不会单独造成占用判断。

单元测试同时覆盖“第二写入者被拒绝”和“残留锁文件可重新打开”。

## 4. 页面字段

### 学期与作息

| 实体 | 主要字段 |
|---|---|
| 学年 | 名称、开始日期、结束日期 |
| 学期 | 所属学年、名称、日期、周数、每周上课日 |
| 作息表 | 所属学期、名称、上课日、基础课节分钟数、默认标记 |
| 课节 | 作息表、星期、序号、标签、开始/结束时间 |

### 基础资料

| 实体 | 主要字段 |
|---|---|
| 年级 | 名称、代码、排序 |
| 教师 | 姓名、工号、部门、在用状态 |
| 教室类型 | 名称、代码、说明 |
| 教室 | 名称、编号、类型、容量、状态 |
| 班级 | 名称、年级、学期、班主任、固定教室、人数、分组 |
| 科目 | 名称、代码、类别、默认连续课时、专用教室要求 |

引用下拉框全部来自当前本地项目，不访问 Supabase。
