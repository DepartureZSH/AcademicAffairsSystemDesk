## 登录配置修正版

首轮构建没有设置 `STT_SUPABASE_PUBLISHABLE_KEY`，`option_env!` 返回空值；旧构建脚本缺少预检，因而生成了有签名但无法进入登录页面的安装包。这不是账号、网络或数据库迁移问题。

修复后：

- `build-windows.ps1` 只读取构建进程或 `.env` 中的三个白名单变量：`STT_SUPABASE_PUBLISHABLE_KEY`、`SUPABASE_PUBLISHABLE_KEY`、`SUPABASE_ANON_KEY`，不执行 dotenv 内容，不导入其他变量。
- 缺少公开 key、传入 secret key 或 JWT 角色不是 `anon` 时，在打包前直接失败。Cargo Release 构建同样拒绝缺失或错误类型的配置，避免绕过 PowerShell 时再次漏检。
- 包含公开 key 的编译环境只在本次构建期间生效，结束后还原；不会输出 key，也不会把 `.env` 作为资源分发。
- `Test-DesktopEmbeddedConfig.ps1` 检查编译后的主程序；`Test-WindowsRelease.ps1` 进一步从安装包解出主程序，再检查公开配置、已知服务端凭据和签名。
- 114 项 Python 测试通过，其中 11 项新增构建配置回归测试。使用本机配置对身份服务 `/auth/v1/settings` 进行只读核验，返回 HTTP 200；未操作账号，也未替用户执行密码登录。

公开 key 可随桌面客户端分发，secret/service-role key 不可。此次白名单和拒绝规则依据 [Supabase API keys 官方说明](https://supabase.com/docs/guides/getting-started/api-keys)。

修正版仍为 v0.1.11，需要重新获取本次生成的 EXE；请不要重复运行旧文件。普通用户无需创建环境变量、修改登录页或提供后台配置。
