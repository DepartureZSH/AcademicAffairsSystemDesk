# 需求追踪与发布就绪审计

> 审计日期：2026-08-31
> 审计分支：`codex/desktop-local`
> v0.1.5 测试制品源码：`2d4dec8d920634e3109afdd5cd4ec2360d108849`

## 1. 结论

产品需求规格中的本地桌面主体流程已经闭环；教务业务数据、算法输入输出、候选、日志、导入、导出和备份均使用本地真实实现，不以 Mock 返回业务成功。当前开发配置中的身份认证和旧版数据源连接本机 Docker Supabase；许可证、支付、SMTP 和远程更新仍由 `config/services.yaml` 明确标记为 Mock。

因此可以结束“本地主体功能补齐”阶段并进入最新 Windows 制品重建，但不能把当前状态称为生产正式版。生产发布还受真实远程服务、SignPath 或测试签名策略以及干净 Windows 虚拟机验收约束。

## 3. 当前自动化证据

- Python：项目 `.venv` 执行 `python -m pytest -q`，88 passed。
- Python 静态检查：`uv run ruff check .`，通过。
- Rust：`cargo fmt --check`、`cargo check --locked`、`cargo test --locked`，14 passed。
- Vue：`npm run build`，类型检查和生产构建通过。
- 真实本地 Auth：注册、邮箱确认、旧密码登录、恢复 token、更新密码、旧密码拒绝、新密码登录闭环通过，临时用户和邮件零残留。
- 冻结 Sidecar：真实 EXE 完成项目 → 计划 → 预检 → 两轮 warm start 排课 → 五种导出 → 备份校验/恢复 → 项目归档导出/导入 → 授权关闭，零硬违例、零进程和临时目录残留。
- 启动时限：Supabase Auth 连接/整请求超时固定为 3/5 秒；v0.1.5 冻结 Sidecar 在 5 秒门槛下 3,756 ms 就绪，Rust 超时单元测试与制品级生命周期脚本均通过。干净 Windows 的窗口交互就绪计时仍列为人工门槛。
- 跨平台 PDF：内置 Noto Sans SC Variable，固定上游提交/大小/SHA-256/OFL-1.1；wheel 和 PyInstaller CArchive 均包含字体及许可证，SBOM 记录为独立文件组件。
- 规模：6000 课次、250 名教师、150 个班级、240,000 个候选动作，25.762 秒得到 6000 条完整课表，硬约束 0、总分 0。
- 列表性能：基础资料使用 50 条服务端分页；10 万条合成记录在五个偏移位置完成计数、排序读取和 JSON 序列化的最大耗时为 66.304 ms，低于 300 ms 目标。
- 真实本地迁移：最大源项目迁入 239 个任务、488 个课次、207 条约束、6 个历史候选和 2,859 条课表项；SQLite 完整性为 `ok`、外键问题 0。

性能结果只代表当前 Windows 11 开发机；发布候选仍需在最低支持配置重复验证。

## 5. Windows 发布门槛

公开测试版 [`v0.1.5-test.6`](https://github.com/DepartureZSH/AcademicAffairsSystemDesk/releases/tag/v0.1.5-test.6) 精确对应源码 `2d4dec8d920634e3109afdd5cd4ec2360d108849`。NSIS/MSI 外层安装包、桌面主程序和 Sidecar 均有测试 Authenticode 签名及 DigiCert RFC3161 时间戳；对最终安装包字节生成的 Tauri updater Ed25519 签名也已实际验签。发布包含 9 个资产，远端重新下载后 7 条 `SHA256SUMS` 内容记录全部复算一致。

NSIS 不再只依赖 `allowDowngrades=false`。项目固定 Tauri 2.11.5 官方模板来源并在 `.onInit` 前置执行 `KariosAbortDowngrade`；本地模拟 9.0.0 测试以退出码 10 拒绝安装 0.1.5。更重要的是，[真实升级/降级运行](https://github.com/DepartureZSH/AcademicAffairsSystemDesk/actions/runs/33352330535) 已从两个不可变 release 验证 `v0.1.4-test.5 → v0.1.5-test.6`：NSIS 与 MSI 都能升级，旧安装器均不能覆盖新版文件，用户工作区保持；NSIS 降级退出码 10，MSI 为 1603。

[干净 Windows 运行](https://github.com/DepartureZSH/AcademicAffairsSystemDesk/actions/runs/33352330538) 的三个矩阵均通过：Windows Server 2025 AMD64 的 NSIS/MSI，以及 Windows 11 ARM64 对 x64 NSIS 的兼容运行。证书导入前签名为 `UnknownError`，临时信任后为 `Valid`；内层两个 EXE 已验证、主程序可启动、卸载后用户工作区保持。

仍需人工执行的 Windows 门槛只剩：

- 原生 x64 硬件上的干净 Windows 10 和 Windows 11 客户端安装/启动/卸载抽检；
- 从进程启动到窗口真正可交互的 10 秒人工或 UI 探针计时；
- SignPath 获批后的正式 Publisher、来源验证与签名链复验。

不得把 Windows 11 ARM64 的 x64 仿真结果表述为原生 Windows 10/11 x64 验收完成。完整发布证据见 `56-v0.1.5-test.6发布与验收证据.md`。

SignPath Foundation 获批前只发布明确标记的自签名测试版；获批后正式直发包的 Publisher 预期为 “SignPath Foundation”。
