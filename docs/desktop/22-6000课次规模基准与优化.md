# 6000 课次规模基准与优化

## 1. 验收数据

`benchmarks/benchmark_6000.py` 确定性生成以下本地项目：

- 250 名教师；
- 150 个班级；
- 5 天、每天 8 节，共 40 个可用课节；
- 每班 40 个启用课次，共 6000 课次；
- 240,000 个“课次 × 时间”候选动作；
- 固定随机种子 `20260831`。

每个班级使用独立教师，课表填满 40 个课节，因此数据可行且可重复。该数据专用于验证目标规模、完整候选持久化和时间门槛，不替代包含混合连堂、专用教室和复杂软约束的兼容性样本。

运行命令：

```powershell
uv run python benchmarks/benchmark_6000.py --time-budget 60
```

默认在系统临时目录创建隔离工作区，结束后删除；也可用 `--workspace <路径>` 保留项目供分析。

## 2. 首次测量与瓶颈

同一台 Windows 11 x64 验收机首次测量：

| 阶段 | 耗时 |
| --- | ---: |
| 数据生成 | 0.283 秒 |
| 问题编译 | 1.824 秒 |
| CP-SAT 调用 | 65.794 秒 |
| 候选持久化 | 0.269 秒 |
| 候选可见总耗时 | **67.888 秒** |

CP-SAT 内部模型构建耗时 28,948.8 ms，可行性搜索 16,528.7 ms，质量搜索 15,827.5 ms。该结果生成了完整 6000 条课表，但超过 60 秒门槛，不能验收通过。

## 3. 安全优化

排课器本来就先执行硬约束感知的贪心构造，并把结果作为 CP-SAT hint。优化后，在创建 240,000 个布尔变量之前检查：

1. 是否为全部课次生成了安排；
2. 贪心选择过程是否已通过全部启用的硬约束；
3. 时间、教室和软分布罚分之和是否严格等于 0。

所有罚分均为非负整数，因此 0 是目标函数的理论全局下界。三个条件同时成立时，继续建立 CP-SAT 模型不可能得到更低分，结果可标记为 `OPTIMAL_ZERO_LOWER_BOUND`。任一课次未排或任一罚分大于 0 时，仍执行完整 CP-SAT 建模和搜索；自动测试用“所有时段均有正罚分”的反例验证不会错误进入快路径。

非快路径的搜索预算也改为扣除模型构建耗时，防止“60 秒搜索预算 + 额外模型构建时间”长期突破用户配置的轮次预算。

## 4. 验收结果

同一数据、设备和随机种子复测：

| 阶段 | 耗时 |
| --- | ---: |
| 数据生成 | 0.282 秒 |
| 问题编译 | 1.808 秒 |
| 本地算法 | 25.048 秒 |
| 候选事务持久化 | 0.178 秒 |
| 候选可见总耗时 | **27.035 秒** |

最终状态为 `succeeded`，硬约束违例 0、软罚分 0，并验证 SQLite 中恰有 6000 条对应候选的课表记录。结果低于 60 秒门槛 32.965 秒。

机器环境与结构化结果保存在 `benchmarks/results/windows-6000-20260831.json`。性能数字只代表该验收设备；发布前仍需在最低支持配置的干净 Windows 10/11 虚拟机重复运行。

完成本地主体功能审计后，在提交 `44bca391c0e463504cf0cc436fb3335724dd867f` 上再次使用同一命令复测：数据生成 0.281 秒、问题编译 1.717 秒、本地算法 23.871 秒、持久化 0.174 秒，候选可见总耗时 **25.762 秒**。结果仍为 6000 条完整课表、硬约束 0、总分 0，结构化数据作为 `latestRevalidation` 保留在同一 JSON 中，原始首次验收数据没有被覆盖。

## 5. 后续规模覆盖

质量矩阵还应保留：

- 真实脱敏小样本兼容性；
- 6000 课次零罚分可行基准；
- 有正罚分、必须进入 CP-SAT 的中大型优化基准；
- 明确不可行且能输出定位诊断的规模基准；
- 独立算法进程取消、内存压力、磁盘写满和强制退出恢复测试。
