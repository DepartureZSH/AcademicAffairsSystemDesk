# 课表查看、手工调整与冲突检查

## 1. 不可变候选原则

自动候选和手工候选都不可原地覆盖。用户移动一个课次时，应用先进行无副作用预检；只有预检通过才创建新的 `manual` 轮次和子候选，并复制完整课表结果。父候选、评分、课表明细和 Solution XML 保持不变。

因此“撤销”不依赖易丢失的内存栈：界面直接切回父候选即可。手工候选仍可作为自动优化的 warm start。

## 2. 课表视图

“课表与导出”入口当前提供：

- 全部课表网格；
- 班级课表筛选；
- 教师课表筛选；
- 教室课表筛选；
- 年级课表筛选；
- 候选切换、得分和课次数显示；
- 旧数据候选提示。

候选快照 Revision 与当前项目 Revision 不同时显示“旧数据候选”。旧候选仍可查看，不会因为基础资料修改而被覆盖。

## 3. 即时冲突检查

手工移动提交前会在候选绑定的不可变输入快照上重建合法选项并检查：

- 目标星期、开始课节和连续课时是否是合法作息窗口；
- 教师、班级、课次和教室的可用性；
- 固定教室、教室类型和默认教室候选范围；
- 教师同一时段冲突；
- 班级同一时段冲突；
- 教室同一时段冲突；
- 所有启用的通用硬分布约束；
- 每日最大课时和最大连续课时等候选后置硬校验。

有任一硬冲突时返回 `valid=false` 及阻断课次/约束，不写数据库。即使客户端绕过“预检”按钮直接请求创建，服务端也会再次校验，并以 `409 MANUAL_MOVE_CONFLICT` 拒绝。

软约束会重新计分。新候选保存新的 Solution XML、课表条目和指标，并记录 `manual_move_applied` 追加事件。

## 4. 本地接口

- `GET /v1/timetables/{candidate_id}`：返回完整课表，可按 `teacher`、`homeroom`、`room` 筛选。
- `POST /v1/timetables/validate-move`：无副作用冲突预检。
- `POST /v1/timetables/manual-fork`：服务端重复校验后创建不可变子候选。

所有接口只读取本地 SQLite 和项目快照，不发出网络请求。

## 5. 验证

自动测试覆盖：

- 移到已占用课节会返回资源硬冲突；
- 绕过预检直接创建仍被拒绝；
- 移到空闲合法课节会创建父子关系正确的新候选；
- 父候选课表保持逐条不变；
- 修改基础资料后旧候选被标记为基于旧数据；
- Python 全量测试和 Vue TypeScript 生产构建通过。

Excel、CSV、PDF、Problem XML 和 Solution XML 已接入当前候选视图；展示型导出支持范围、单双周、横纵版式和彩色/黑白预览，详见 `27-年级课表候选比较与导出预览.md`。
