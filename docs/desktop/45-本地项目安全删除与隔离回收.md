# 本地项目安全删除与隔离回收

## 1. 用户流程

本机项目列表为每个已关闭项目提供“删除”操作。界面先展示项目名称和准确绝对路径，并连续执行两次原生确认；当前打开的项目必须先关闭，排课轮次运行期间也不能删除。

删除不会立即递归擦除目录。项目会从 `workspace/projects/<project-id>` 原子移动到 `workspace/trash/projects/<project-id>-<timestamp>-<random>`，从活动项目列表消失，但完整 SQLite、附件、算法制品和日志仍在隔离回收区，可按故障处理流程人工恢复。

## 2. 存储安全边界

- 项目 ID 必须是规范 UUID，解析后的源目录必须是 `projects` 的直接子目录。
- 目标目录必须是 `trash/projects` 的直接子目录，名称包含 UUID、UTC 时间和随机后缀。
- 客户端提交确认时同时提交列表中看到的项目名称；名称已变化则拒绝，要求刷新后重新确认。
- 删除前获取项目文件锁；被其他进程打开的项目拒绝回收。
- 获取锁后写入 `.stt.deleting.json`，记录项目 ID、名称、原路径、删除时间和可恢复标记；之后才移动目录。
- 打开项目时若看到删除标记会拒绝，避免释放文件锁到原子移动之间出现新的打开竞争。
- 移动失败时清理源目录中的删除标记，项目继续保留在原位置。

整个操作只在同一用户选择的工作区内重命名目录，不调用递归删除，也不访问网络。

## 3. 本地接口

`DELETE /v1/projects/{project_id}` 接收：

```json
{
  "expected_name": "2026 学年第一学期",
  "confirmed": true
}
```

成功响应返回原路径、隔离回收路径、删除时间和 `recoverable=true`。未确认、名称不匹配、当前项目未关闭、文件锁占用、路径越界或运行中排课均拒绝。

## 4. 验证

自动测试覆盖文件锁拒绝、名称匹配、确认门禁、当前项目门禁、原目录移除、回收目录和删除记录存在、活动列表移除，以及已回收项目不能再按原 ID 打开。

## 5. 人工恢复参考

恢复前完全退出桌面应用，避免工作区或目标项目被占用。打开回收目录中的 `.stt.deleting.json`，核对 `project_id`、`name` 和 `original_path`；若原路径已经存在，停止操作，不得覆盖。

在 PowerShell 中使用实际路径替换示例值：

```powershell
$sttTrashProject = 'D:\STT-Workspace\trash\projects\<回收目录名>'
$sttOriginalProject = 'D:\STT-Workspace\projects\<project-id>'

$resolvedTrash = (Resolve-Path -LiteralPath $sttTrashProject).Path
if (Test-Path -LiteralPath $sttOriginalProject) { throw '原项目路径已存在，禁止覆盖' }
Move-Item -LiteralPath $resolvedTrash -Destination $sttOriginalProject
Remove-Item -LiteralPath (Join-Path $sttOriginalProject '.stt.deleting.json')
```

重新启动应用后，项目应重新出现在本机项目列表。先打开项目并执行完整备份与 SQLite 完整性检查；如 manifest、数据库或附件校验失败，将目录移回隔离区并按备份恢复流程处理。
