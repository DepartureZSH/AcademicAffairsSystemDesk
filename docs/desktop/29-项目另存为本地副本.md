# 项目另存为本地副本

## 1. 模块结论

项目工作台现已补齐“新建、打开、另存、关闭最近项目”的本地项目生命周期。“另存为”在当前工作目录中创建一个拥有全新项目 ID 的可编辑副本并自动打开；源项目及其数据保持不变。

## 2. 可信复制流程

另存没有直接递归复制活动项目目录，而是复用 `.sttproj` 的完整可信链路：

1. 将当前 SQLite、manifest、附件和算法制品暂存；
2. 为每个文件记录 SHA-256 和字节数；
3. 生成临时 `.sttproj` 并立即重新验证文件清单、哈希、SQLite 完整性和外键；
4. 导入为全新项目 ID，更新数据库与 manifest 中的项目标识和名称；
5. 再次打开副本并执行最终完整性检查；
6. 无论成功或失败都删除工作区内的临时项目包。

副本不继承工作区级备份记录，因为这些记录指向源项目的备份文件；账号令牌、设备私钥和授权凭证本来就不属于项目内容。

## 3. 并发与失败行为

- 排课工作进程运行时拒绝另存，避免捕获不完整的求解状态；
- 副本名称必须为 1 到 200 个非空字符；
- 导入成功前不会关闭源项目；
- 目标使用随机 UUIDv7 目录，不覆盖任何已有项目；
- 任一步失败都会清理经过父目录和前缀校验的暂存目录及临时包。

## 4. 验收

- 副本项目 ID 与源项目不同，名称采用用户输入；
- 教师、附件、Revision 和其他项目内容保持一致；
- 修改副本不会改变源项目；
- 临时 `project-save-as-*.sttproj` 在完成后不存在；
- API 成功后自动打开副本并返回其项目资料和 Revision；
- Python、Vue、Rust 全量回归继续通过。
