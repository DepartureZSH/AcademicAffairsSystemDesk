# `.sttproj` 项目归档与迁移

## 1. 用途与边界

`.sttproj` 是“时奕教务排课”的可移植项目包，用于在本机工作区之间或不同电脑之间迁移一个项目。它包含项目 SQLite 一致性快照、项目 manifest、附件以及本地算法与导出产物。

它与 `.sttbackup` 的职责不同：

- `.sttproj` 面向用户主动迁移和分享项目副本；
- `.sttbackup` 面向自动保护、操作前恢复和灾难恢复；
- 两者都不会包含账号令牌、设备私钥、企业密钥或许可证凭证；
- 工作区级 `.sttbackup` 文件不嵌套进项目包，导入时会清除来源项目的备份记录，避免保留失效路径。

## 2. 导出流程

1. 对当前项目使用 SQLite Backup API 创建一致性数据库快照；
2. 复制项目 manifest、`attachments/` 和 `artifacts/`；
3. 为每个文件记录相对 POSIX 路径、SHA-256 和字节数；
4. 写入严格字段集合的 `project-package.json`；
5. 在临时文件生成 ZIP 并重新执行完整校验；
6. `fsync` 后原子替换用户选择的 `.sttproj` 目标文件。

已存在的目标只有在用户通过原生另存对话框明确选择覆盖后才能替换。数据库日志、工作区备份以及外部目标绝对路径不进入项目包。

## 3. 导入流程

1. 用户通过 Tauri 原生对话框选择 `.sttproj` 并明确确认；
2. 校验扩展名、ZIP 条目、路径、符号链接、总解压大小和异常压缩比；
3. 流式重新计算每个文件的大小与 SHA-256；
4. 交叉核对外层 manifest、项目 manifest 和 SQLite 内的项目 ID、Schema 与 Revision；
5. 执行 SQLite 完整性和外键检查；
6. 生成全新的项目 ID，在隔离临时目录更新副本；
7. 清除未随包迁移的工作区备份记录；
8. 原子移动到 `projects/<新项目ID>/` 并再次打开做最终完整性检查；
9. 成功后打开新项目，任何现有项目都不会被覆盖。

若最终检查失败，只删除本次新建且路径已严格核对的目标目录，来源 `.sttproj` 与现有项目保持不变。

## 4. 限制与安全规则

- 最多 20,000 个文件；
- 解压后总大小最多 5 GiB；
- 单项压缩比最多 1,000；
- 拒绝绝对路径、Windows 驱动器路径、反斜杠路径、`..` 路径穿越、重复文件名和符号链接；
- 拒绝高于当前应用支持范围的包格式或 SQLite Schema；
- 导入只能创建新项目，不能指定现有项目 ID 或覆盖目录；
- `.sttproj` 提供完整性检测，不提供机密性或来源签名。需要传输敏感教务项目时，应额外使用组织批准的加密介质或加密容器。

## 5. 本地接口

- `POST /v1/project-archives/export`：导出并校验当前项目；
- `POST /v1/project-archives/import`：明确确认后导入、打开新项目。

接口仅由 Tauri 随机本机端口代理调用，仍受一次性 sidecar 会话令牌和本机 Origin 限制。

## 6. 自动验证

测试覆盖项目数据与附件往返、新项目 ID、备份记录清理、SQLite 完整性、目标覆盖门禁、扩展名检查、路径穿越、文件篡改及三层 manifest/数据库 Revision 不一致拒绝。
