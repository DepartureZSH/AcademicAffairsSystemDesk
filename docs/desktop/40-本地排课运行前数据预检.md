# 本地排课运行前数据预检

## 1. 模块结果

“排课运行”页面现在提供独立的数据预检。预检只读取当前 SQLite Revision，在内存中编译与正式求解相同的本地问题模型，不创建数据快照、排课轮次、候选或制品，也不递增 Revision。

用户可手工点击“立即检查”；点击“生成第一轮候选”或“继续优化”时也会强制重新预检。存在阻断项时不会启动算法进程。

## 2. 检查范围

- 是否存在活跃教学任务、启用课次、可用作息和启用课节。
- 每个课次是否至少有一个符合星期、连续课时、可用性和优先时段硬约束的候选位置。
- 活跃教学任务是否分配了存在且启用的主讲教师。
- 教学任务周课时是否等于启用课次的连续课时合计。
- 课程计划周课时是否等于其活跃教学任务合计。
- 固定教室是否存在且启用，是否满足要求的教室类型。
- 要求的教室类型是否至少有一个启用教室；网页版 `__no_room__` 明确无教室语义除外。
- 用户约束是否成功编译；不能编译的约束作为警告展示。
- 对象分配的作息没有启用课节时，回退到可用默认作息并展示警告。

预检只能发现无需完整搜索即可确认的问题。资源组合在全局上是否可行仍由本地 CP-SAT 求解器判断；求解无解时继续遵守“不给出伪候选”的门禁。

## 3. API

```http
POST /v1/validation/preflight
```

响应包含当前 Revision、输入哈希、检查时间、任务/课次/候选位置统计、`ready`、阻断项和警告。请求体为空，不接收或上传教务数据。

## 4. 自动与真实数据验证

- 有效小项目预检通过，且前后 Revision、`data_snapshots` 和 `scheduling_rounds` 数量不变。
- 缺失教师和课程计划/教学任务课时不平衡会返回稳定错误码。
- 空项目通过本机 API 返回 `NO_ACTIVE_LESSONS`、`NO_BELL_SCHEDULE`，不创建排课轮次。
- 真实本地 Supabase 项目迁移后：239个活跃任务、488个课次、17,160个候选位置、0个阻断项、4个作息回退警告；预检前后 Revision 均为1。
