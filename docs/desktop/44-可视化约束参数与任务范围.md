# 可视化约束参数与任务范围

## 1. 完成范围

“约束配置”页面不再暴露 JSON 文本框。首发支持的四类规则均使用结构化控件创建和编辑，并由桌面端生成 Sidecar 已验证的规范化参数：

| 规则 | 可视化参数 | 本地参数 |
| --- | --- | --- |
| 每日最大课时 | 上限、教师/班级统计范围、教学任务范围 | `max`、`resourceType`、`teachingTaskIds` |
| 连续授课限制 | 上限、教师/班级统计范围、教学任务范围 | `maxConsecutive`、`resourceType`、`teachingTaskIds` |
| 同科课次分散 | 教学任务范围 | `teachingTaskIds` |
| 优先时段 | 一个或多个节次、教学任务范围 | `periods`、`teachingTaskIds` |

教学任务留空表示作用于全部有效任务。界面使用“班级 · 科目 · 教师”显示任务，节次按当前项目所有作息表的 `period_index` 去重展示。优先时段未选择任何节次时禁止保存。

## 2. 求解与校验语义

- `preferred_periods` 只作用于所选教学任务或课次；硬规则删除非优先节次选项，软规则仅对非优先节次计入配置权重。
- `same_day_spacing` 对每个选中任务分别建立不同日条件；选择多个任务不会把不同任务的全部课次错误合并为一个互斥组。
- `max_daily_lessons` 和 `consecutive_limit` 在原生求解阶段与候选解后校验阶段使用相同的任务和资源范围。
- 手工调课重新构建候选绑定快照的问题模型，只能选择该课次的合法时间和教室选项；因此不能绕过硬优先时段或其他已编译硬约束。

旧项目可继续包含 `lessonIds` 精确课次范围，Sidecar 会与 `teachingTaskIds` 一并识别。当前页面只写入教学任务范围，避免教务人员在任务重建课次后留下失效的单课次引用。

## 3. 旧版数据兼容

SQLite schema 和既有 `parameters` 存储格式不变，不需要项目迁移。四类已支持规则会解析原参数并回填控件；无法识别的导入约束仍在列表展示，但编辑按钮禁用，只允许保留或删除，防止可视化表单覆盖其原始语义。

## 4. 自动验证

- 硬优先时段限定 `task-1` 时，另一个教学任务仍可按自身必须可用规则排入非优先节次。
- 每日上限限定 `task-1` 时，解后校验不会把同教师、同班级的其他任务课次计入该规则。
- Vue 类型检查和生产构建验证多选值、旧参数解析及保存载荷。
- 完整 Python 回归覆盖自动排课、手工调整、候选保存和既有约束语义。
