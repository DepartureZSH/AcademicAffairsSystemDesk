# 课程计划、教学任务与约束实现记录

## 1. 课程计划流程

当前项目打开后，“课程计划”页面提供两层本地业务对象：

1. 课程计划：选择学期、班级和科目，设置每周课时、连续课时、连堂允许和优先级；
2. 教学任务：可从课程计划带入字段，再分配主教师、教室类型、固定教室和启用状态。

课程计划和教学任务均支持新增、编辑、列表和删除。页面中的引用只来自当前 SQLite 项目，不查询远端 Supabase。

## 2. 教学任务与课次原子生成

教学任务通过专用接口 `PUT /v1/planning/tasks` 保存。Sidecar 在一次 `BEGIN IMMEDIATE` 事务中：

1. 校验 `expected_revision`；
2. 新增或更新 `teaching_tasks`；
3. 删除该任务以前的自动生成课次；
4. 按每周课时与连续课时重新展开 `task_lessons`；
5. 只递增一次项目 revision；
6. 提交后原子更新 manifest。

例如每周 5 课时、连续 2 课时会生成时长 `[2, 2, 1]` 的三个课次。更新为每周 4 课时后会在一个 revision 中重建为 `[2, 2]`。任何中途错误都会回滚任务和课次，避免出现半生成状态。

## 3. 约束配置

“约束配置”页面分为：

- 规则约束：每日最大课时、同科课次分散、连续授课限制、优先时段和自定义规则；
- 可用时段：为教师、班级、教室或具体课次设置必须可用、不可用或带 penalty 的偏好。

每条规则包含 hard/soft 严重程度、权重、启用状态和 JSON 参数。Sidecar 对 `parameters` 执行 JSON 解析，并要求顶层必须是对象；无效 JSON 不进入 SQLite。

教师、班级、教室同一时段不可冲突属于排课算法的内置硬约束，不依赖用户手工创建规则。算法模块接入时会把本表规则编译为求解器输入，并记录编译版本与输入哈希。

## 4. 删除与引用

- 删除教学任务会由 SQLite 级联删除其课次；
- 删除课程计划会把已存在教学任务的 `course_plan_id` 置空，不删除教学任务；
- 删除被课程计划/任务引用的班级或科目受外键限制；
- 所有界面删除操作都先显示确认提示。

高风险批量变更的“操作前自动备份”将在备份恢复模块接入，当前模块不把该后续能力描述为已完成。

- `test_planning_task_endpoint_generates_lessons_atomically`：验证真实 FastAPI 协议和 `[2,2,1]` 结果；
- `test_constraint_parameters_require_json_object`：验证非法 JSON 和数组顶层被拒绝；

- Rust 桌面层与 Python 全量测试通过。

## 6. 后续算法边界

本模块只建立权威本地输入，不生成伪候选。下一阶段会：

- 生成不可变数据快照和输入哈希；
- 编译内置硬约束、可用时段和用户规则；
- 调用本地 Python/OR-Tools 构造可行解并优化；
- 保存候选、评分、诊断和完整轮次事件；
- 对硬约束无解返回可定位冲突，不创建“看似成功”的候选。
