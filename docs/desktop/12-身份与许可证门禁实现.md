# 身份与许可证门禁实现记录

> 2026-09-05 更新：默认会员模式已接入同账号在线权益校验，不再要求企业密钥。以 [58-账号会员联网授权](58-账号会员联网授权.md) 为准；下文是旧 Mock 阶段的实现记录。

## 1. 已实现范围

本模块实现桌面应用进入本地算法服务前的身份和设备授权门禁：

- 通过 Rust 可信层调用 Supabase Auth 的邮箱密码登录、注册、完整密码恢复、刷新和退出接口；
- 只接受 HTTPS Supabase endpoint，本机回环开发环境例外允许 HTTP；
- 将 Supabase 会话写入系统凭据库，不写入 localStorage、SQLite、日志或 WebView；
- 首次激活时生成设备 Ed25519 密钥，将私钥写入系统凭据库，只展示公钥摘要形成的设备指纹；
- 根据 `config/services.yaml` 运行 7 天本地 Mock 许可证；
- 本地授权声明绑定 Supabase 用户 ID 和设备指纹，并由设备私钥签名以检测意外篡改；
- 在系统凭据库保存只增不减的授权时钟检查点，超过5分钟容差的明显回拨会阻止启动 Sidecar；
- 只有许可证有效时 Rust 才允许启动 Python Sidecar；
- 退出账号时停止 Sidecar，删除会话和本地授权，保留设备私钥。

Windows 使用 Windows Credential Manager。后续 macOS/Linux 由同一 `keyring` 抽象切换到 Keychain/Secret Service。

## 2. 可信边界

Vue WebView 只接收以下脱敏状态：

- 是否已配置、已登录、离线；
- 用户邮箱和 Supabase 用户 ID；
- 许可证模式、是否有效、到期时间、设备指纹和设备上限。

以下内容不会返回 Vue：

- access token、refresh token；
- 设备私钥；
- 系统凭据库内容；
- Supabase publishable key 的值；
- 用户输入的密码和企业密钥。

密码恢复是唯一例外：用户从邮件复制的完整恢复链接和新密码会经 Tauri IPC 一次性传给 Rust 可信层。Vue 在调用前立即清空三个输入引用；Rust 只在进程内存中解析并消费恢复 token，不把链接、token、新密码或恢复会话写入日志、SQLite、系统凭据库或响应。恢复成功后，现有登录会话和本地授权均被删除，用户必须用新密码重新登录并激活。

Windows 凭据目标仅用于定位，不包含凭据值：

- `supabase-session.tech.karios.stt.desktop`；
- `device-ed25519.tech.karios.stt.desktop`；
- `mock-entitlement.tech.karios.stt.desktop`。
- `license-clock-checkpoint.tech.karios.stt.desktop`。

publishable key 虽然是公开客户端参数，开发环境仍只通过 `STT_SUPABASE_PUBLISHABLE_KEY` 注入，避免环境差异被硬编码。service-role、JWT secret 和数据库密码绝不进入桌面进程。

## 3. Mock 许可证

开发配置中 `services.license.mode` 为 `mock`。本地测试激活码固定为：

```text
KARIOS-MOCK-LOCAL-2026
```

它是公开测试夹具，不是生产企业密钥。校验对输入和期望值分别做 SHA-256，并使用恒定时间比较。激活后凭证包含：

- 版本和 `mock` 模式；
- 当前 Supabase 用户 ID；
- 当前设备指纹；
- 签发时间和 7 天到期时间。

Mock 只验证桌面状态机和离线门禁，不声称实现跨设备三台额度、退款、风控或服务端撤销。真实模式在接口未部署时明确拒绝启动，不会自动退回 Mock。

每次读取有效授权时，可信 Rust 层会比较当前系统时间与凭据库中的最大已见时间。5分钟以内允许操作系统校时误差；更大幅度回拨立即使授权失效且不覆盖原检查点。生产环境应通过真实许可证续签完成联网校验；当前 Mock 环境可重新输入测试企业密钥重置检查点。退出登录不会删除检查点，避免通过反复退出绕过检测。

## 4. 开发启动

现有网页版仓库包含本机 Supabase publishable key 时，在桌面仓库执行：

```powershell
.\scripts\start-desktop-dev.ps1
```

脚本默认读取同级 `STT\.env`，也可用 `-SupabaseEnvFile` 指定其他文件。脚本不打印 key，结束后清除临时注入的环境变量。

若直接运行 `npm run tauri:dev`，需要预先设置：

```powershell
$env:STT_SUPABASE_PUBLISHABLE_KEY = '<publishable-key>'
```

不要把实际值写入 Markdown、YAML、Git、终端历史或对话。

## 5. 已执行验证

2026-08-31 在本机 Docker Supabase 和 Windows 桌面进程完成：

1. 未登录时 Sidecar 不启动，所有业务导航保持禁用；
2. 使用临时、已确认的合成账号完成真实 Supabase 密码登录；
3. 登录后仍不能启动 Sidecar，界面要求输入企业密钥；
4. 输入 Mock 激活码后创建三项 Windows Credential Manager 凭据并启动 Sidecar；
5. Sidecar 只监听 `127.0.0.1` 随机端口，原有本地 SQLite 项目可正常读取；
6. 退出后 Sidecar 立即停止，会话和授权凭据被删除，仅设备私钥保留；
7. 授权签名篡改、设备指纹稳定性、激活码精确匹配和5分钟时钟回拨容差通过 Rust 单元测试；
8. 真实执行注册 → 邮箱确认 → 旧密码登录 → 恢复邮件 → 恢复 token 换取短期会话 → 更新密码 → 旧密码拒绝 → 新密码登录；
9. TypeScript/Vite 构建、Rust 格式/编译/测试和 Python 全量测试通过。

可重复验收命令：

```powershell
.\scripts\Test-LocalSupabaseAuth.ps1
```

脚本只允许本机回环 Supabase/Mailpit 地址，publishable key 只从环境文件读取且不输出；每次生成独立合成账号，并按用户 UUID 和邮件 ID 精确清理。合成测试账号与两封邮件在验证后均已删除；未使用用户真实账号或生产服务。

## 6. 后续真实服务切换

将 `services.license.mode` 切为 `real` 之前必须完成：

- Supabase 私有 `license` schema 和 RLS/grant 审计；
- 激活 nonce、设备签名、三设备额度和风险限流；
- 服务端 Ed25519 JWS 签发、`kid` 轮换和客户端当前/上一公钥验证；
- 7 天续签、明确撤销/退款立即阻断和时钟回拨联网校验；
- Edge Function、邮件 outbox、支付履约和端到端安全测试。

在这些条件完成前，真实许可证模式保持失败关闭（fail closed）。
