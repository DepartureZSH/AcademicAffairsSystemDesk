# 资源课时上限原生求解约束

## 1. 修复结论

`max_daily_lessons`（每日最大课时）和 `consecutive_limit`（连续授课限制）已从“求解后才校验”升级为本地 CP-SAT 搜索阶段的原生资源约束。求解器会主动寻找满足硬上限的另一种排法，不再因为第一个候选违反上限而误报整个问题无解；软上限也进入质量目标，能在剩余时间内主动降低罚分。

## 2. 编译模型

生成 `problem.xml` 时，桌面 sidecar 按教师和班级分别展开资源组，并为每条启用规则写入 `limits/limit`：

- 约束 ID、名称、范围；
- 类型与上限；
- 硬/软属性及软约束权重；
- 该教师或班级关联的稳定课次 ID。

每日最大课时按课节占用数计算，连堂两节计为两个课时。连续限制按 `periodIndex` 的连续占用窗口建模；任意长度为 `上限 + 1` 的窗口都不能被完全占满。这个定义同时覆盖单节课和连堂课。

## 3. 硬约束与软约束

- 硬上限直接加入 CP-SAT 线性约束，参与最大可排课次数的可行性证明；
- 软上限创建非负超额变量，按 `超额课时 × 权重` 加入质量目标；
- 资源上限存在时禁用“零罚分贪心直接返回”捷径，贪心结果只作为 CP-SAT hint；
- 最终评分把资源软上限计入 `distribution_penalty`，并设置内部标记避免 sidecar 事后校验再次重复加分；
- 手工移动继续执行同义的最终校验，拒绝违反硬上限的移动并为软上限计分。

## 4. 冲突诊断

若硬资源上限确实导致某课次无法安排，无解说明会携带：

- `MAX_DAILY_LESSONS` 或 `CONSECUTIVE_LIMIT`；
- 约束 ID、名称、教师/班级范围和上限；
- 未排入的课次及当前证明状态。

这保持“硬约束无解时可定位，不能伪造候选”的产品规则。

## 5. UI 边界

约束页只保留当前有真实实现的四类可视化规则：每日最大课时、同科课次分散、连续授课限制和优先时段。新建表单不再提供会被静默忽略的任意 `custom` 类型；若打开旧项目发现该遗留类型，会显示为禁用选项，便于用户识别并替换或删除。

## 6. 自动验收

- 仅有周一时段、两课次且每日上限 1：证明无解并返回 `MAX_DAILY_LESSONS`；
- 增加周二时段后：同一数据成功排出，两个课次自动分散到两天；
- 三课次、连续上限 2 且存在周二时段：成功找到不含三节连续占用的候选；
- 软每日上限：进入质量求解并得到零超额方案，总分不重复计算；
- 原有 6000 课次基准、手工移动、候选评分和无解诊断继续回归。
