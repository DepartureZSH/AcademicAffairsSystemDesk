# 十万条本地列表分页与性能门禁

## 1. 问题与目标

产品需求把“常用列表在 10 万条以内的交互响应目标为 300 毫秒以内”列为性能目标。此前 `/v1/data/{entity_type}` 会返回全部记录，基础资料页也会一次创建全部 Vue DOM 行；即使 SQLite 查询足够快，10 万条 JSON 传输和 DOM 渲染也无法满足该目标。

## 2. 实现

- `ProjectRepository.list_entities_page` 使用实体白名单中的表名与排序表达式，提供 `LIMIT/OFFSET` 和同快照连接上的总数查询。
- 分页大小强制为 1–500，偏移不得为负数；FastAPI 使用相同边界生成 422 参数错误。
- 原有不带参数的实体接口保持兼容，现有排课、约束、课表和导入模块的小规模关联加载不受影响。
- TypeScript 客户端可显式传入 `limit/offset`，响应同时返回 `total/limit/offset/revision`。
- 基础资料可见列表固定每页 50 条，只创建当前页 DOM；标签显示数据库总数，翻页时丢弃编辑态，避免在错误页继续编辑。
- 教师、班级、教室等关联选择缓存最多 500 条，高于产品规模目标（250 名教师、150 个班级）。这不是面向 10 万教师的通用通讯录搜索器；若未来放宽产品规模，必须先将原生 `<select>` 改为服务端检索选择器。

## 3. 自动化验证

仓储测试构造 120 名教师并验证第二页顺序、总数、500 条上限和负偏移拒绝；HTTP 测试验证分页元数据和超限 422。全量 Python 测试为 86 passed，Ruff 和 Vue 类型检查/生产构建通过。

独立性能脚本：

```powershell
uv run python scripts/Test-LocalListPerformance.py
```

脚本在系统临时目录创建项目，以单个事务写入 100,000 条确定性合成教师记录，分别读取开头、四分之一、中间、末页和再次开头。每个样本包含 `COUNT(*)`、稳定排序、50 条行转字典和紧凑 JSON 序列化；不把合成数据提交到仓库，也不接触用户工作区。

2026-08-31 当前 Windows 11 x64 开发机结果：

| 指标 | 结果 |
| --- | ---: |
| 记录数 | 100,000 |
| 每页 | 50 |
| 五次耗时 | 12.821 / 25.410 / 40.783 / 66.304 / 12.665 ms |
| 中位数 | 25.410 ms |
| 最大值 | 66.304 ms |
| 门槛 | 300 ms |
| 结论 | 通过 |

## 4. 证据边界

此门禁验证本地数据层到 JSON 边界，并通过固定 50 行限制消除大规模 DOM 风险；它不声称自动测量最终 WebView 的点击到绘制帧。最终签名安装包仍需在最低支持硬件上人工抽查翻页交互。分页接口属于新 Sidecar 源码，下一测试发布必须重新冻结 Sidecar 并执行全流程，不得沿用 `v0.1.0-test.1` 的旧二进制作为制品证据。
