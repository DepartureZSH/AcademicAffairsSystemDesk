# 网页版 Supabase 数据本地迁移

## 1. 目的与边界

本模块将已有网页版排课项目从 Supabase PostgreSQL 下载到用户选择的本地工作区。迁移完成后，桌面项目只读写自己的 `project.sqlite3`，不向 Supabase 反向同步，也不在运行排课时访问旧数据库。

迁移使用 PostgreSQL `REPEATABLE READ READ ONLY` 事务，保证所有表来自同一一致性快照。数据库 URL 仅通过进程环境变量传入，不写入 YAML、日志、manifest 或 Git。

## 3. 字段映射

| 网页版表 | 本地实体 | 处理规则 |
| --- | --- | --- |
| `terms` | `terms` | 保留学期日期、周数、工作日数，生成新 UUIDv7 |
| `weekly_timetable_templates` | `bell_schedules` | 同时读取项目模板分配；不依赖项目自身 `term_id` |
| `weekly_timetable_periods` | `time_slots` | 保留星期、节次索引、起止时间和显示配置 |
| `teachers` | `teachers` | 迁移工号、姓名、部门、状态；不迁移手机号和账号 ID |
| `homerooms` | `homerooms` + `grades` | 由 `group_name` 生成本地年级并重建关联 |
| `subjects` | `subjects` | 保留代码、类别、默认时长和专用教室要求 |
| `room_types` / `rooms` | 同名本地实体 | 重建类型、默认教室和容量关联 |
| `course_plans` | `course_plans` | 保留周课时、时长、单双周/工作日位图和优先级 |
| `teaching_tasks` | `teaching_tasks` | 重建班级、科目、教师、课程计划和教室关联 |
| `task_lessons` | `task_lessons` | 保留课次索引、时长、位图和旧 XML class ID |
| `project_timetable_template_assignments` | `timetable_template_assignments` | 重建教师、班级、科目、教室类型、教室或全局对象关联；悬空引用跳过并告警 |
| `user_constraint_templates` / `itc_distribution_constraints` | `constraints` | 合并用户语义和编译结果，重建课次/任务引用；不支持的约束保留但停用 |
| `scheduling_runs` | `scheduling_rounds` | 保留时间预算、算法、种子和状态；未完成的旧轮次转为可恢复失败状态 |
| `solution_versions` | `candidates` / `candidate_metrics` | 硬约束为0的候选可用；有违例或已替代的候选仅供只读查看和比较 |
| `timetable_entries` | `timetable_entries` | 优先按课次 UUID、其次按旧 XML class ID 重建关联；无法关联的历史条目仍保留 |

所有源业务 UUID 都重新映射为本地 UUIDv7。旧 XML class ID 仅作为课次兼容标识保留。远端 `organization_id`、`user_id`、手机号、账号资料、数据库 URL 和访问令牌不会写入教务项目。迁移告警进入本地 `validation_issues`，也会出现在命令行 JSON 的 `warnings` 字段中。

网页版以5分钟等底层刻度保存 `start_slot`、`length_slots` 和课程时长，桌面版以“第几课节、连续几课节”保存。迁移器根据各作息模板的课节长度自动换算：例如网页版 `length_slots=8`、`slot_duration_minutes=5` 会转为桌面 `length_slots=1`、`slot_duration_minutes=40`，历史课表的起始刻度也映射为课节序号。发生换算时写入 `LEGACY_TIME_GRID_NORMALIZED`，避免把一节40分钟课程误判成连续8节课。

## 4. 操作命令

从桌面仓库根目录执行：

```powershell
# 只列出本机 stt-local 中的项目和规模
.\scripts\import-local-supabase.ps1

# 将选定项目导入 Git 忽略的本地工作区
.\scripts\import-local-supabase.ps1 `
  -ProjectId '<从上一步选择的 UUID>' `
  -Workspace '.local\workspace'
```

脚本从 `supabase status -o env` 读取当前本地连接，只在子进程期间设置 `STT_LEGACY_DATABASE_URL`，结束后立即清除。不要把生产数据库 URL 写进参数、PowerShell 历史或配置文件。

## 5. 失败处理

- 源数据库不存在或不是本机地址：拒绝连接。
- 项目不存在：不创建本地项目。
- 字段或外键不兼容：基础数据、约束、历史轮次、候选、课表项和告警在同一事务中回滚，不产生半套业务数据；事务外刚写入的快照文件也会清理。
- 本地项目目录已创建但批量导入失败：保留空项目供诊断，不自动删除用户文件。
- 旧项目没有直接 `term_id`：从课程计划、教学任务、班级和作息模板联合解析学期。
- 更高版本数据库出现新字段：未知字段不会自动透传，必须更新显式映射和测试。

## 6. 历史候选使用限制

- `valid` 候选可查看、比较、导出、手工调整和作为下一轮 Warm start。
- `invalid` 或 `superseded` 历史候选可查看和比较，但桌面端和本地 API 都禁止导出、手工调整及 Warm start。
- 无法关联课次的历史课表项可以显示其现有班级、教师、科目、教室和时间信息，但不能参与课次级手工移动。
- 迁移不会把旧候选重新判定为可行；要得到满足当前桌面约束的候选，应在本地创建新会话并重新求解。
