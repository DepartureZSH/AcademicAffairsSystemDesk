### 数据与安全边界

- 教务存储和执行仍在本机，AI 不持有 SQLite、Shell 或任意 SQL 执行权限。只有用户确认的结构化动作才能写入；项目版本变化后必须重新预览。
- 提供商密钥仅由 Rust 从系统密钥库读取；本地 Python 只组装请求和处理结果，不保存或接触提供商密钥。浏览器开发预览不会保存密钥或直接调用提供商。
- 超大附件拒绝处理，不静默截断导入；受限文件格式、字段、规则或含糊范围在保存前明确报错。
- 云端共享约束模板不复制到本地；保留本地常见约束与 Excel 模板。五个场景与网页版一致，排课启动仍在“排课运行”页，不向模型新增后台自动排课权限。

## 第三次执行：本地 service、工具和审核执行（历史记录）

下方“第二次执行”是历史记录；本节覆盖其中的对话、持久化、模板和审核接口状态。

- `scripts/sync-ai-service.cjs` 从网页仓库机械同步 compiler、tools、business_prompts、official_workbooks、workbook_layouts、workbook_presentation 和 distributions；来源 SHA-256 保存在 `sidecar/stt_desktop/agent/upstream/provenance.json`。网页 service 中的云端账号、额度及数据库依赖不直接复制，本地编排在 `agent/service.py`。
- 使用原版按场景工具定义、项目查询、名称解析、依赖排序、actions 编译与逐项执行器。Rust `ai_complete` 转发兼容 Chat Completions 的 tools/tool_calls，不再走仅建议的 `ai_chat`。模型须支持工具调用。
- 本地流程：确认数据发送范围 → 保存消息 → 模型请求 → 白名单工具查询/提案 → 整批编译 → 回滚事务预检 → 展示原版变更审核面板 → 用户确认 → 校验备份 → 单次 SQLite 事务写入数据与审核状态。拒绝、跨项目请求、过期项目版本、重复确认均有处理。模型不能执行任意 SQL 或脚本。
- schema 6 增加项目内 AI 文档表；对话、工具上下文、待审核动作和执行结果持久化。业务修订号不因聊天而增加；一批动作只增加一次修订号。清空记忆保留审核记录。
- 可执行：教师、班级、科目、教室类型、教室台账的常规操作；学期更新；课表模板与节次；课程计划和授课任务/课次；本地算法支持的明确课次分布约束。web 的 5 分钟课长转换为本地分钟配置，不直接作为课节数。
- 官方学校、教室和课程计划 Excel 模板直接使用网页工作簿生成器；桌面使用保存对话框，浏览器预览使用下载。不覆盖已有文件。

### 仍有明确边界

这不是全量复刻完成：课表区域 AI 识别/分区生成、期望时间专项选择器、约束向导搜索与展开接口仍需继续适配；目前可通过各场景的普通对话走上述工具链。仅支持本地 `time_slot_id/week_bits/penalty` 格式的期望时间，其他网页时间选项格式拒绝转换。新课次与引用其预分配 ID 的约束不能跨场景一次提交，应先执行课次后查询实际 ID。已有授课任务的科目默认课长变更暂要求在科目台账操作，避免覆盖逐课次配置。未实现流式输出、模型自动修复编译错误与网页完整导入覆盖率核验。任一不支持的字段/约束必须在审核前报错，不允许静默丢弃。
