# 时奕教务排课桌面应用与本地数据架构

> 本文定义桌面运行时、本地数据、sidecar 协议、排课轮次和备份格式。远程身份与许可证见《02-身份许可证支付与风控架构》。

## 1. 总体结构

```text
┌───────────────────────────────────────────────────────────┐
│ Tauri 2 桌面进程                                          │
│  ├─ Vue 3 UI                                              │
│  ├─ Rust 命令层：文件、凭据、授权、sidecar、更新          │
│  └─ Stronghold/Windows Credential Manager                 │
├───────────────────────────────────────────────────────────┤
│ 127.0.0.1 随机端口 + 每次启动令牌                         │
├───────────────────────────────────────────────────────────┤
│ Python sidecar                                            │
│  ├─ 本地应用服务                                          │
│  ├─ SQLite repository                                     │
│  ├─ XML adapter / validator                               │
│  └─ OR-Tools / Solution Pool LNS 排课引擎                 │
├───────────────────────────────────────────────────────────┤
│ 用户选择的工作目录：项目、附件、候选、导出、备份          │
└───────────────────────────────────────────────────────────┘
```

远端连接不经过 sidecar。Rust 授权层或最小化的前端认证适配层只访问预先声明的 Supabase 与更新域名。任何本地业务 repository 都不得实现远端同步接口。

## 2. 进程与信任边界

### 2.1 Tauri 主进程

职责：

- 创建窗口并执行导航白名单、CSP 和 Tauri capability 限制。
- 通过系统文件选择器打开和保存项目。
- 调用安全存储，不向 WebView 暴露私钥或完整 refresh token。
- 验证设备授权后启动 sidecar。
- 生成每次启动独立的 256 位 sidecar 会话令牌。
- 管理 sidecar 健康检查、异常退出、取消和优雅关闭。
- 校验并安装更新。

### 2.2 Vue 前端

职责：

- 复用现有组件和交互流程，但通过桌面数据适配器访问本地 API。
- 展示授权状态、项目状态、数据编辑、排课进度和候选结果。
- 不直接读写项目文件、不执行系统命令、不保存长期秘密。
- 购买操作调用 Tauri 命令打开系统浏览器，不在特权 WebView 加载购买站点。

### 2.3 Python sidecar

职责：

- 打开一个项目数据库，并确保单项目单写入者。
- 执行本地 CRUD、导入、校验、XML 转换、排课和导出。
- 所有 HTTP 请求必须拒绝非回环来源、缺失令牌和错误 `Origin`。
- 默认禁止出站网络；算法和本地业务功能不得依赖网络。

sidecar 启动参数不得包含访问令牌。建议由 Tauri 在进程启动后通过继承的匿名管道传入会话令牌；若首版只能使用环境变量，变量必须只存在于子进程环境并在初始化后从内存配置中清除。

## 3. Sidecar 生命周期与本地协议

### 3.1 启动

1. Tauri 验证本地授权或成功在线续签。
2. 预留 `127.0.0.1:0` 随机端口并生成启动 nonce。
3. 启动与平台匹配的 sidecar 二进制。
4. sidecar 返回端口、进程 ID、协议版本和 nonce 签名。
5. Tauri 调用 `/v1/health` 并验证响应。
6. 前端只拿到由 Tauri 封装的命令，不直接持有 sidecar 令牌。

### 3.2 API 分组

| 分组 | 主要能力 |
| --- | --- |
| `/v1/health` | 进程、协议、算法和数据库驱动版本 |
| `/v1/projects` | 新建、打开、关闭、归档、校验 |
| `/v1/data/*` | 学期、班级、教师、科目、教室、计划、任务、约束 |
| `/v1/imports` | 解析、预览、确认或放弃导入 |
| `/v1/validation` | 数据、XML 和候选校验 |
| `/v1/rounds` | 新建、查询、取消排课轮次 |
| `/v1/candidates` | 查看、比较、选择、导出候选 |
| `/v1/backups` | 创建、列出、校验、恢复备份 |

所有变更接口接收 `expected_revision`。版本不匹配返回 `409 REVISION_CONFLICT`，前端提示重新加载，不执行隐式覆盖。

统一错误结构：

```json
{
  "error": {
    "code": "PROJECT_SCHEMA_TOO_NEW",
    "message": "当前应用无法打开由更高版本创建的项目。",
    "details": {},
    "correlationId": "local-random-id"
  }
}
```

## 4. 工作目录与文件格式

### 4.1 目录布局

```text
<用户选择的工作目录>/
  projects/
    <project-id>/
      project.sqlite3
      manifest.json
      attachments/
      artifacts/
        problem/
        solution/
        exports/
      logs/
  backups/
    <project-id>/
  temp/
```

`manifest.json` 至少包含：格式版本、项目 ID、名称、创建时间、最后保存时间、应用版本、数据库 schema 版本、校验和算法协议版本。目录中的绝对路径不得写入数据库或归档。

### 4.2 `.sttproj`

- ZIP 容器，固定 UTF-8 文件名。
- 包含 `manifest.json`、SQLite 数据库、附件和重现所需算法制品。
- `manifest.json` 保存每个文件的 SHA-256、大小和逻辑用途。
- 导入时解压到新的随机临时目录，阻止 `../`、绝对路径、符号链接和解压炸弹。
- 完整校验通过后才原子移动到 `projects/<project-id>`。

### 4.3 `.sttbackup`

- 与项目归档采用相同容器基础，但 `kind` 固定为 `backup`。
- 增加备份原因、来源项目路径、来源 revision 和应用构建号。
- 恢复不得直接覆盖活动项目；先恢复为临时副本并运行 `PRAGMA integrity_check`、manifest 校验和 schema 检查。

## 5. SQLite 设计原则

- 开启外键：`PRAGMA foreign_keys=ON`。
- 正常运行使用 WAL；生成归档前执行 checkpoint 并复制一致性快照。
- 所有业务写入在事务中完成，并递增项目 revision。
- 时间使用 UTC ISO 8601 或 Unix 毫秒，界面按本地时区显示。
- 主键使用 UUIDv7 或等价的有序随机 ID，禁止把远端 Supabase 用户 ID 写入教务业务实体。
- schema 迁移只允许向前执行。打开更高版本 schema 时只读拒绝，不尝试降级。
- 大型导入、XML、Excel 和 PDF 不存入 BLOB；存附件并保存相对路径、哈希和元数据。

### 5.1 本地领域分组

| 分组 | 核心实体 |
| --- | --- |
| 项目 | project、academic_year、term、bell_schedule、time_slot |
| 学校数据 | grade、homeroom、teacher、subject、room、room_type |
| 教学计划 | course_plan、teaching_task、task_lesson |
| 约束 | availability_rule、constraint、constraint_member、compiled_constraint |
| 运行 | data_snapshot、optimization_session、scheduling_round、round_event |
| 结果 | candidate、timetable_entry、candidate_metric、validation_issue |
| 文件 | attachment、import_job、export_job、artifact、backup_record |

### 5.2 迁移流程

1. 获取项目排他锁。
2. 校验磁盘剩余空间至少为项目大小的 2 倍加 500 MB。
3. 创建 `pre-migration` 备份并验证。
4. 在数据库事务中逐版本迁移。
5. 执行外键、完整性和领域不变量检查。
6. 更新 manifest 和校验和。
7. 任一步失败则保留原项目和恢复点，并输出可复制诊断信息。

## 6. 排课会话与轮次模型

### 6.1 状态

`optimization_session`：`draft / active / completed / cancelled`。

`scheduling_round`：`queued / preparing / solving / validating / succeeded / infeasible / cancelled / failed`。

`candidate`：`valid / invalid / superseded`；只有 `valid` 可成为下一轮父候选或正式导出对象。

### 6.2 输入与输出

每轮固定记录：

- 数据快照 ID 和输入哈希。
- 父候选 ID，可为空。
- 时间预算、随机种子、求解器版本和算法参数。
- 初始解来源、迭代次数、最佳目标值和停止原因。
- 输出候选、硬约束数、各类软约束分数和验证器版本。

首轮流程：数据预检 → 构造可行初始解 → 验证 → 在剩余预算内优化 → 最终验证 → 保存候选。

后续轮次：读取所选父候选 → 验证其输入快照仍匹配 → 注入 warm start → LNS/repair → 保存新的子候选。父候选不可修改。

### 6.3 取消与崩溃恢复

- Tauri 发送取消请求后，求解器在安全检查点停止。
- 超过 5 秒未停止时终止工作进程，但不得杀死桌面主进程。
- 轮次事件使用追加写；应用重启时将遗留 `preparing/solving/validating` 标记为 `failed_recoverable`。
- 只有完整通过验证的候选才在单个事务中写入可见结果。

## 7. 备份策略

自动触发点：

- schema 迁移前。
- 批量导入确认前。
- 大规模删除、恢复或替换项目数据前。
- 每个自然日首次成功保存后。
- 用户手工创建。

保留规则：每项目默认保留最近 10 份成功自动备份；手工标记“保留”的备份不参与自动淘汰。清理只删除通过 manifest 定位且位于当前项目备份目录内的文件。

详细恢复步骤见《07-备份恢复与故障处理》。

## 8. 本地安全与日志

- 应用日志与项目日志分离，默认保留 14 天。
- 日志中的文件路径默认只显示项目名和末级文件名；导出诊断包前再次脱敏。
- 本地 API 记录方法、路由、耗时、结果码和 correlation ID，不记录请求体。
- CSP 默认 `default-src 'self'`，远端认证和更新请求通过明确 allowlist。
- 关闭 Tauri 未使用插件和命令；每个窗口配置最小 capability。
- sidecar 和迁移脚本随安装包签名并在启动前校验 SHA-256 清单。

## 9. 跨平台适配点

| 能力 | Windows 首版 | 后续适配 |
| --- | --- | --- |
| 安全存储 | Stronghold + Windows Credential Manager/DPAPI | Keychain、Secret Service |
| sidecar | Windows x64 独立可执行文件 | macOS universal、Linux x64/arm64 |
| 安装器 | NSIS 主、MSI 备 | DMG、AppImage/deb |
| 签名 | 自签名测试 / SignPath 正式 | Apple Developer ID、Linux 包签名 |
| 更新 | Tauri updater | 沿用同一 manifest 协议 |

业务数据库、归档格式和算法 I/O 必须保持平台无关；仅平台适配层可以出现条件编译。

## 10. 架构验收检查

- [ ] 许可证无效时 sidecar 不启动。
- [ ] sidecar 只监听回环地址，错误令牌一律返回 401。
- [ ] 断网后所有教务 CRUD、排课、导出仍可运行。
- [ ] 网络请求记录中没有业务数据字段或附件。
- [ ] 项目归档在另一台 Windows 设备上可打开并复现候选。
- [ ] 迁移失败可恢复原项目，数据库完整性检查通过。
- [ ] 取消或强制关闭算法不会产生可见半成品候选。
- [ ] 6000 课次基准满足产品性能目标。
