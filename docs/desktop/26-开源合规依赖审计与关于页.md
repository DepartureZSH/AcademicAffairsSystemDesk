# 开源合规、依赖审计与关于页

## 1. 模块结论

仓库已在 Apache-2.0 `LICENSE` 和 `NOTICE` 基础上补齐隐私、安全、商标、代码签名、贡献和第三方依赖说明。桌面应用新增无需登录或许可证即可访问的“关于与开源”页，显示版本、应用标识、本地数据边界、漏洞报告方式、签名政策和第三方构建限制。

这些文本是工程与发布基线，不替代生产服务上线前对主体信息、客服渠道、IP 保存期限、购买条款和适用法律的人工审核。

## 2. 新增公开文件

- `PRIVACY.md`：本地教务数据、远程身份/许可证边界、IP 安全日志、无遥测默认和用户控制；
- `SECURITY.md`：支持版本、私下漏洞报告与秘密/学校数据禁传规则；
- `TRADEMARKS.md`：Apache-2.0 与官方名称、图标、标识符、更新端点和签名身份的边界；
- `CODE_SIGNING_POLICY.md`：可签名范围、公开来源、作者/审阅者/批准者、测试与 SignPath 正式流程；
- `CONTRIBUTING.md`：锁定依赖、测试命令、数据/秘密和架构约束；
- `THIRD_PARTY_NOTICES.md`：生成式依赖清单、主要运行组件、PyInstaller 例外和字体策略。

## 3. 依赖许可证清单

执行：

```powershell
uv run python scripts\generate_dependency_inventory.py
```

脚本离线读取当前 uv 环境、`package-lock.json` 和 `cargo metadata --locked`，输出被 Git 忽略的 `build/compliance/dependency-inventory.json`。任何依赖缺少许可证元数据时返回非零退出码，阻止 CI 制品阶段。

加入官方 Tauri opener 后，本次本机清单共 647 项：Python 44、npm 26、Cargo 577，缺失许可证元数据 0。Cargo 数量包含锁文件中跨平台条件依赖，属于保守的可审计上界；发布证据保留完整 JSON 而不是易过期的手工表格。

Windows CI 将清单与无签名安装包一起上传，后续自签名或 SignPath 流水线必须关联同一 commit 的清单。

## 4. 资产审计

- 应用图标来自仓库项目资产，并受商标政策约束；
- 未打包网络字体、商业字体、模型文件或远程脚本；
- PDF 在本机选择微软雅黑/黑体等已安装 CJK 字体，不复制字体到安装包；找不到字体时明确失败；
- Vue 前端、Rust 主程序、Python sidecar 和冻结依赖均由锁文件可追溯构建；
- PyInstaller 自身的 GPL 条款及生成可执行文件分发例外在第三方说明中明确记录。

## 5. 关于页门禁

“关于与开源”导航不依赖 Supabase 配置、登录、许可证或当前项目。它不加载远程网页，也不把远程内容放入拥有 Tauri 权限的 WebView。正式政策文件名与官方仓库地址以纯文本显示，避免未配置安全外链适配器前引入任意导航能力。

`LICENSE`、`NOTICE`、隐私、安全、商标、代码签名和第三方说明同时作为安装包 `legal/` 资源随应用离线分发，不能只依赖 GitHub 在线可用性。

## 6. 验收

- `uv run python scripts/generate_dependency_inventory.py`：643 项，缺失 0；
- Vue 生产构建读取真实 Tauri 版本 API，浏览器预览使用安全回退；
- 关于页在未登录/未授权状态可访问；
- CI 保存依赖清单并在缺失许可证元数据时失败；
- 仓库和安装配置不包含 PFX、私钥、密码、service-role 或生产学校数据。
