## 1. 结论

产品需求规格中的本地桌面主体流程已经闭环；教务业务数据、算法输入输出、候选、日志、导入、导出和备份均使用本地真实实现，不以 Mock 返回业务成功。当前开发配置中的身份认证和旧版数据源连接本机 Docker Supabase；许可证、支付、SMTP 和远程更新仍由 `config/services.yaml` 明确标记为 Mock。

因此可以结束“本地主体功能补齐”阶段并进入最新 Windows 制品重建，但不能把当前状态称为生产正式版。生产发布还受真实远程服务、SignPath 或测试签名策略以及干净 Windows 虚拟机验收约束。

## 3. 当前自动化证据

- Python：项目 `.venv` 执行 `python -m pytest -q`，84 passed。
- Python 静态检查：`uv run ruff check .`，通过。
- Rust：`cargo fmt --check`、`cargo check --locked`、`cargo test --locked`，12 passed。
- Vue：`npm run build`，类型检查和生产构建通过。
- 真实本地 Auth：注册、邮箱确认、旧密码登录、恢复 token、更新密码、旧密码拒绝、新密码登录闭环通过，临时用户和邮件零残留。
- 冻结 Sidecar：真实 EXE 完成项目 → 计划 → 预检 → 两轮 warm start 排课 → 五种导出 → 备份校验/恢复 → 项目归档导出/导入 → 授权关闭，零硬违例、零进程和临时目录残留。
- 规模：6000 课次、250 名教师、150 个班级、240,000 个候选动作，25.762 秒得到 6000 条完整课表，硬约束 0、总分 0。
- 真实本地迁移：最大源项目迁入 239 个任务、488 个课次、207 条约束、6 个历史候选和 2,859 条课表项；SQLite 完整性为 `ok`、外键问题 0。

性能结果只代表当前 Windows 11 开发机；发布候选仍需在最低支持配置重复验证。
