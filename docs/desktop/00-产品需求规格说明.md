# 时奕教务排课桌面版产品需求规格说明

> 文档状态：首次执行基线稿
> 产品名称：时奕教务排课
> 应用标识：`tech.karios.stt.desktop`
> 首发平台：Windows 10/11 x64
> 更新日期：2026-08-30

## 1. 文档目的

本文定义桌面版的产品范围、用户流程、业务规则、非功能要求和验收边界。它是后续设计、开发、测试和发布的共同基线。未在本文范围内的能力不得由实施人员自行扩展。

## 2. 产品定位与目标用户

时奕教务排课桌面版面向中小学教务主任、排课负责人和经授权的排课工作人员。产品以“本机完成教务数据维护和排课计算”为核心，解决以下问题：

- 在无持续网络连接时维护学校排课数据并运行算法。
- 用可视化流程替代直接编辑 XML 或数据库。
- 在限定时间内生成可行候选，并允许基于选定候选继续优化。
- 通过本地项目归档、备份和导出实现数据自主保存与迁移。
- 通过远程账号和企业许可证核验官方发行版使用权，但不上传教务业务数据。

首版按单台计算机、单个当前操作用户设计，不提供多人实时协作。

## 3. 产品范围

### 3.1 首版包含

1. 账号与授权
   - 邮箱注册、邮箱验证、密码登录、密码重置和退出登录。
   - 首次使用企业密钥激活当前设备。
   - 查看当前许可证状态、到期时间和当前设备状态。
   - 已激活设备在授权有效期内最多离线使用 7 天。

2. 本地项目
   - 新建、打开、另存、关闭最近项目。
   - 设置用户选择的项目工作目录。
   - 导入、导出 `.sttproj` 项目归档。
   - 自动备份、手工备份及 `.sttbackup` 恢复。

3. 排课基础数据
   - 学年、学期、周次、星期和作息节次。
   - 年级、班级、教师、科目、教室及教室类型。
   - 教师任课关系、教学任务和课程计划。
   - Excel/CSV 批量导入、模板导出和导入校验。

4. 计划与约束
   - 按班级配置课程计划和每周课时。
   - 配置不可用时间、连堂、分散、优先时间、教师负载、教室要求等约束。
   - 将可视化约束编译为算法支持的标准约束。
   - 在运行前检查缺失数据、课时不平衡和明显硬约束冲突。

5. 排课与结果
   - 手工排课、移动课次、撤销和冲突提示。
   - 自动生成初始可行候选。
   - 默认每轮优化 60 秒，允许用户配置轮次时长。
   - 选择历史候选作为下一轮 warm start。
   - 保留每轮候选、评分、算法配置、运行日志和校验结果。
   - 按班级、教师、教室和年级查看课表并比较候选差异。

6. 输出
   - Excel、CSV、PDF、`problem.xml` 和 `solution.xml`。
   - 输出前预览范围、版式、单双周和颜色模式。
   - 导出文件完全写入用户选择的位置。

### 3.2 首版明确排除

- AI 助手及 AI 数据录入。
- 个人资料中心、头像、职务等资料维护。
- 机构创建、机构认证、成员和角色管理。
- 平台审核与原 SaaS 平台管理功能。
- 云端保存、同步、协同编辑和云端算法运行。
- 将教师、班级、课程、约束、课表、XML、算法日志或导入文件发送到远端。
- 移动端应用和浏览器离线版。

许可证运营页面属于发行基础设施，不属于桌面版“平台管理”功能。

## 4. 核心用户流程

### 4.1 首次安装与激活

1. 用户安装并启动应用。
2. 应用生成不可导出的设备私钥，并保存到系统安全存储。
3. 用户完成邮箱注册、验证和登录。
4. 无许可证时，应用提供“购买许可证”和“输入企业密钥”入口。
5. 购买入口在系统浏览器打开 `dean.karios.site` 的购买页面。
6. 支付确认后，企业密钥发送到付款账号邮箱。
7. 用户输入密钥；服务端校验登录账号、许可证、设备签名和设备额度。
8. 激活成功后保存 7 天设备授权凭证，并允许创建或打开本地项目。

### 4.2 日常启动

1. 读取安全存储中的账号会话、设备私钥和授权凭证。
2. 有网络时刷新 Supabase 会话和设备授权。
3. 无网络但授权凭证仍有效时进入离线模式。
4. 服务端明确返回退款、暂停、撤销或账号不匹配时，立即清除可续签状态并阻止进入业务界面。
5. 授权过期且无法联网时，仅显示登录、授权说明、网络诊断和退出，不启动算法 sidecar。

### 4.3 建立排课项目

1. 选择本地工作目录并创建项目。
2. 配置学期、周次和作息。
3. 手工录入或导入班级、教师、科目、教室。
4. 配置课程计划、教学任务和约束。
5. 运行数据预检并修复阻断问题。
6. 创建首轮排课任务。

### 4.4 迭代排课

1. 首轮先构造满足硬约束的可行解，再在剩余时间内优化。
2. 默认轮次时长为 60 秒，设置范围为 10 秒至 30 分钟。
3. 每轮完成后新增不可覆盖的候选记录。
4. 用户比较候选并选择一个作为下一轮起点。
5. 用户可以取消当前轮次；取消后保留上一个完整候选，不保存半成品。
6. 若输入数据本身不可行，返回涉及实体、约束和修复建议，不以软约束得分掩盖硬冲突。

## 5. 关键业务规则

- 可发布或导出的正式候选必须为硬约束 0 违例。
- 同一项目在任一时刻只允许一个自动排课轮次运行。
- 每个候选绑定不可变的数据快照、算法配置、父候选和随机种子。
- 修改影响求解的数据后，旧候选仍可查看，但标记为“基于旧数据”。
- 打开旧版本项目并迁移 schema 前必须生成恢复点。
- 删除项目、覆盖归档和恢复备份都必须二次确认并显示准确路径。
- 许可证限制官方发行版的使用权，不改变 Apache-2.0 赋予第三方的源码修改权。

## 6. 数据边界与隐私

### 6.1 只保存在本地

- 学校、年级、班级、教师、科目、教室和教学任务。
- 作息、课程计划、约束及其编译结果。
- `problem.xml`、`solution.xml`、候选、评分、日志和导出文件。
- 导入原文件、项目快照和备份。

### 6.2 可发送到远端

- 邮箱、Supabase 用户 ID 和认证会话。
- 订单、支付状态、许可证状态和到期时间。
- 设备随机 ID、公钥及公钥指纹，不采集硬盘序列号等稳定硬件标识。
- 应用版本、授权结果码、可信代理解析出的 IP 和安全限流数据。

客户端必须提供可审计的网络请求白名单。新增任何上传字段前必须更新隐私文档和自动化测试。

## 7. 非功能要求

### 7.1 性能

- 在验收设备上，包含 250 名教师、150 个班级和约 6000 课次的可行合成项目，首轮应在默认 60 秒内返回可行候选。
- 常用列表在 10 万条以内的交互响应目标为 300 毫秒以内，不含文件导入和算法运行。
- 启动后 10 秒内显示可交互主界面；sidecar 启动失败必须在 5 秒内给出诊断。

### 7.2 可靠性

- 业务写入使用事务；程序崩溃不得破坏上一个已提交版本。
- 关键操作前和每天自动备份，默认保留最近 10 份成功备份。
- 导入、迁移和恢复必须先写临时文件、校验后再原子替换。

### 7.3 安全

- 不在日志、崩溃报告、URL、命令行参数或数据库中记录密码、原始企业密钥、JWT 和私钥。
- WebView 不允许任意远程内容获得 Tauri 特权；购买页面必须在系统浏览器打开。
- 本机 sidecar 只监听 `127.0.0.1` 随机端口，并校验一次性高熵会话令牌。
- 安装包、更新元数据和更新文件必须分别通过 Authenticode 与 Tauri updater 签名校验。

### 7.4 可维护性与跨平台

- UI、领域模型、SQLite schema 和算法协议不包含 Windows 专属业务逻辑。
- 系统凭据、文件对话框、自动更新和安装器通过平台适配层实现。
- 首版只承诺 Windows 10/11 x64；macOS/Linux 在 Windows 稳定发布后进入独立验收。

## 8. 验收定义

首版达到可发布状态必须同时满足：

- 从注册到付款、收信、激活、离线使用和续签的链路通过。
- 核心网页排课流程已在桌面端完成，排除项没有残留入口。
- 网络阻断测试证明教务数据不会离开本机。
- 6000 课次可行基准能产生候选，不可行基准能给出冲突诊断。
- 项目归档、备份恢复和 schema 升降级保护通过破坏性测试。
- Windows 10/11 干净虚拟机安装、升级、卸载和签名验证通过。
- 所有 P0/P1 缺陷关闭，没有泄漏密钥、越权发证或重复履约问题。
