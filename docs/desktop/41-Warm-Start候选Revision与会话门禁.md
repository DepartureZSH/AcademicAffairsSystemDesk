# Warm Start 候选 Revision 与会话门禁

## 1. 模块结果

候选列表现在同时返回候选绑定的数据快照 Revision 和 `based_on_old_data` 标记。只有以下条件全部满足的候选才能作为下一轮 Warm start：

- 候选状态为 `valid`；
- 候选数据快照 Revision 等于当前项目 Revision；
- 候选所属优化会话与请求指定会话一致。

旧数据、含硬约束违例、已替代或跨会话候选仍可按既有规则查看和比较，但不能续跑。界面将它们标记为“只读”，后端 API 同时执行独立强校验，不能通过绕过界面提交非法父候选。

## 2. 失败原子性

父候选校验发生在创建新会话、排课轮次、数据快照和算法制品之前。校验失败不会留下空优化会话、失败轮次或临时文件。

未显式传入会话 ID 且父候选有效时，后端自动沿用父候选所属会话；显式传入其他会话则拒绝，不会静默移动候选历史。

## 3. 验证

- 生成有效候选后修改教师名称，项目 Revision 增加，候选立即标记为 `based_on_old_data=true`。
- 使用该旧候选调用 `prepare_round` 返回稳定错误，轮次和会话数量保持不变。
- 创建两个独立会话后，将会话 A 的候选作为会话 B 的父候选会被拒绝，且不新增轮次。
- 有效、当前 Revision、同会话候选的既有后续优化测试继续通过。
